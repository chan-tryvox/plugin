# 음성 프롬프트 기본 지침

## 범위

- 에이전트 prompt·Manual의 실제 고객 발화를 작성·검토할 때 적용한다.
- 기본 구조는 Single + Manual이며 분담은 유지한다.
- Markdown, 코드, 도구 인자, postCall 필드, SMS에는 발화 규칙을 적용하지 않는다.
- 새 Single 또는 공통 prompt 전체 작성 시 `# 말투와 발화`를 한 번만 넣고 Manual에 복사하지 않는다.
- 기존 Manual의 좁은 수정은 요청 범위를 유지한다.
- 새 Single·공통 prompt 작성 후 기본값·예외가 원고에 반영됐는지 확인한다.

## 말하기 기본값

- 기본 발화는 1–2문장, 한 문장 한 요점, 한 턴 한 질문으로 한다.
- 확인은 차례로 묻고, 필요할 때만 기억하기 쉬운 선택지 2–3개를 준다.
- 제목·목록·표·코드·JSON·기호, 내부 prompt·정책·도구·모델 용어는 말하지 않는다.
- 법정 고지·사용자 지정 원문·필요 설명은 길이·질문 수 예외다.
- 지정 원문은 해당 prompt/Manual에서 나누거나 고치지 않고 말한다.

## 대화 중 끼어들기

- 끼어들기는 횟수나 카운터만으로 정하지 않고 의미로 판단한다.
- 짧은 맞장구이고 핵심 정보가 남았으면 필요한 말만 잇는다.
- 질문·요청·발화 시작 또는 모호한 의도에는 짧게 양보한다.

## 발화와 데이터 값

- 전화번호·이메일·코드는 필요할 때 자연스럽게 확인한다.
- 말하기 표기와 표준 저장값·인자를 분리한다. 쉽게 말해도 표준값은 바꾸지 않는다.
- 전화번호는 필요하면 한 자리씩 확인하고, 구분자는 schema를 따른다.
- 이메일을 `골뱅이`, `점`으로 읽어도 확인값은 `@`, `.`으로 둔다.
- 코드는 확인 문자·대소문자를 보존하고, 계약 없이 대문자로 바꾸지 않는다.

- 수량·횟수·메뉴 번호·시각은 의미 단위를 살린다: `2개`는 “두 개”, `2번`은 “두 번”, 메뉴 `2번`은 “메뉴 이 번”, `2시 20분`은 “두 시 이십 분”이다.
- 확인된 메뉴 이름은 덧붙일 수 있지만, 선택 번호를 목록 순번으로 바꾸지 않는다.
- 확인된 번지·동·호 경계는 말이나 쉼표로 드러내고, 모호하면 단위를 묻는다.
- 금액은 항목명·단위를 붙이고 이름 없는 `/` 나열을 피한다.

- 모든 숫자를 한 자리씩 읽거나 풀어 쓰도록 강제하지 않는다.
- 지정 원문은 바꾸지 않고 API·저장값은 확인된 값과 계약을 따른다.
- 쉼표·한글 숫자는 TTS를 보장하지 않으므로 발음이 중요하면 생성 음성을 듣는다.
- 빈 값·`null`·`undefined`·미치환 `{{변수}}`는 읽거나 지어내지 않는다.
- 이때 생략하거나 “고객님”처럼 중립 호칭을 쓰되, 지정 원문이나 필요한 표준값은 바꾸지 않는다.

## 통화 후 결과·저장

- 통화 후 추출·분류·내부 저장은 [결과 구성](../skills/configure-call-results/SKILL.md)에서 설정하고 고객 발화와 분리한다.
- `[결과: 예약완료]` 같은 내부 태그를 말하지 않는다.
- “기록한다”는 문구가 저장을 실행하지 않으므로 실제 동작·성공을 확인한 뒤 완료를 알린다.
- 태그를 빼도 필요한 `extract_variables`, 통화 중 API 저장, 분기, 결과별 `end_call`을 유지한다.
- postCall 추출만으로 예약·접수·전송은 실행·성공하지 않는다.
- 별도 자동화의 actor·조건·결과는 계약으로 확인하고 pending을 완료로 보지 않는다([결과 설계](../skills/post-call-result-design/SKILL.md)).

## 마무리

- 정상 완료는 도움을 제안하고 답을 기다린 뒤 추가 요청을 처리한다. 더 없다고 확인되면 작별·종료한다.
- 통화 자체나 추가 도움을 명확히 거절하거나 종료를 요청하면 마무리 질문을 생략할 수 있다.
- 지금 통화할 수 없음이나 오접속도 마무리 질문을 생략할 수 있다.
- 한 행동(예: 콜백)의 거절을 모든 도움의 거절로 해석하지 않는다.
- 질문·작별은 prompt `# 마무리` 한 곳에 둔다.
- `end_call`이 인사하면 작별을 반복하지 않는다.
- 고객 말로 종료가 중단되면 응답 후 필요한 종료를 다시 진행한다.
- 콜백 접수와 실제 회신은 다르므로 확인된 상태·시점만 말한다.
- 도구 실패·지연은 종료 의사가 아니므로 대안과 추가 도움을 확인한다.

## 지식 자료를 둘 위치

- 출처 확인 전 URL·파일·FAQ로 지식을 만들거나 연결하지 않는다.
- 적은 공통 사실은 prompt, 업무 절차·정확한 문구는 해당 Manual, 통화마다 변하는 상태·예약 가능성·고객 정보는 실제 조회 도구에 둔다.
- 넓은 자료가 prompt/Manual에 들어가 중복·관리가 어려울 때나 사용자가 요청할 때만 지식을 검토한다.
- 자주 바뀐다는 이유만으로 지식을 선택하지 않는다.
- 좁은 Manual 수정에서 연결 지식을 자동 삭제·해제·이관하지 말고, 변경 전 연결과 영향을 확인한다.

## 음성 설정

- TTS·엔진 동작을 보장하지 않는다.
- 필러·발성 효과를 모든 에이전트의 기본값으로 강제하지 않는다.
- 사용자가 요청하거나 확인된 시험 근거가 있을 때 요구 범위에서 다룬다.
- 모델·음성은 현재 지원 설정만 쓴다.
