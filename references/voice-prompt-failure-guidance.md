# 음성 프롬프트 실패 진단과 최소 수정

실패한 발화나 고객 피드백을 prompt 또는 Manual 문제로 단정하지 말고, 관찰한 기대와 실제 결과를 좁혀 연결한다. 이 지침은 진단과 원고 수정을 위한 것이며 음성 품질을 보장하거나 제품 설정을 대신하지 않는다.

## 진단

1. 기대한 동작과 실제 발화·도구 입력·도구 결과를 가능한 범위에서 나란히 본다. 원문 transcript가 없으면 고객 보고나 제공된 예시로 표시하고 관측 사실처럼 쓰지 않는다.
2. 과거 통화가 있으면 해당 통화의 agent 버전과 이용 가능한 당시 설정을 먼저 확인한다. 현재 prompt만 보고 과거 발화 원인을 단정하지 않는다. [통화 근거 확인](../skills/inspect-call-evidence/SKILL.md)의 범위를 따른다.
3. 증거를 실제 규칙과 연결한다. 공통 음성 기준은 [음성 프롬프트 기본 지침](voice-prompt-guidance.md)과 대조한다. 예를 들면 한 번에 여러 질문, 장황한 발화, 내부 용어 노출, 도구 실패 후 추측, 실제 변경 없이 완료를 말함, spoken 값과 저장값 불일치, 변수 노출, 범위 이탈, 사람 연결 시점을 나눠 본다.
4. 원인을 구분한다: prompt/Manual 규칙의 누락·모호함·충돌, 출처 사실의 부족, 도구 계약·외부 실행 문제, 제품 설정·지연 문제, 또는 기대·시험 조건 문제. 증거가 부족하면 가능한 원인과 미확정 근거를 분리한다.

진단 결과에는 기대, 관찰된 근거와 출처, 어긋난 실제 규칙 또는 설정, 원인 후보와 확신 수준, 부족한 근거를 짧게 담는다. 진단만 요청받았으면 제품 설정이나 원고를 변경하지 않는다. 고정된 실패 사례 수나 출력 YAML을 요구하지 않는다.

## 최소 수정

수정을 요청받으면 해당 실패를 만든 prompt 또는 Manual 부분만 고친다. 주변 문구와 업무 구조를 다시 쓰지 않고, 기존 Manual 선택, 필수 단계와 게이트, 도구 소유·참조, 사용자가 지정한 원문과 보존 조건을 유지한다. 도구 실행 실패나 제품 지연은 근거 없이 발화 규칙으로 덮지 않는다.

수정 후에는 같은 기대 상황에서 무엇이 달라져야 하는지와 중요한 인접 조건 하나를 확인 기준으로 남긴다. 작은 문구 수정에 여러 개의 고정 시나리오나 새 실시간 통화를 강제하지 않는다. 변경 시 저장·revision·재조회는 [기존 Manual 편집](../skills/edit-manual-safely/SKILL.md)의 절차를 따르고, 실제 음성 시험을 하지 않았다면 완료로 표시하지 않는다.
